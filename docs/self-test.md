# Play公開前の本人テスト

## 開始条件

- 署名証明書を確認したEAS `preview` APK
- 公開候補Worker/D1/KV
- APK／Android bundleから `AIza` とプロバイダー秘密値が検出されない
- `npm test`、`expo-doctor`、Worker dry-runが成功
- 開始時のcommit SHAとWorker versionを記録

Play Consoleへは、このテストに合格するまでアップロードしない。

2026-08-01にEAS既存keystoreで署名した `1.0.1`（versionCode 2）のpreview APKを生成し、
APK内の秘密値スキャンと公開Workerの匿名認証・同期・削除を確認した。実機で選択音声の
ラベル欠落が見つかったため、同じkeystoreで `1.0.2`（versionCode 3）をローカルEAS
ビルドした。外部プロバイダー資格情報は未設定のため、AI機能を含む14日計測はまだ
開始していない。表示名とランチャーアイコンを正式な `READING NOTE` へ揃えた
`1.1.0`（versionCode 4）も同じkeystoreで生成・検証した。

## Androidへのインストール

1. 最新候補 `.expo/READING-NOTE-1.1.0-preview.apk` をUSBまたは同一LANでAndroidへ送る。
2. APKを開き、Androidに求められた場合だけ、そのブラウザ／ファイルアプリの
   「不明なアプリのインストール」を一時的に許可する。
3. 旧版のローカル記録を残す場合は、旧版をアンインストールせず、そのままAPKを開いて
   上書きインストールする。署名不一致が表示された場合はアンインストールせず中止する。
4. 起動後、Wi-Fiを切ったモバイル回線でも匿名認証と同期が成功することを確認する。

EAS build `bb4aa4b5-a667-4ed6-8f8e-3837dfc44745` の1.0.1は表示不具合確認済みのため、
新規テストには使わない。APKを公開配布場所へ置かない。

## 最低運用量

- 同一候補版で連続14日
- 実書籍10冊以上
- 紙／JAN本5冊以上、PDF／TXT等のcontent本2冊以上
- 3冊以上に合計20件以上のドッグイヤー
- purpose、link、recap、rating、finishedAt、100冊進捗を使用
- 要約、クイズ、TTS、OCRをそれぞれ実行

## 必須シナリオ

- オフライン編集後の再接続
- バックグラウンドからの復帰
- 2端末または端末＋エミュレーターの同時編集
- 同じ本へ両端末でドッグイヤーを追加し、両方が残る
- `lastSentenceIdx` が巻き戻らない
- 副端末で再インストールし、Google連携から復元
- 旧APKへデータを入れ、同じ署名のpreview APKで上書き
- 専用アカウントで統合三択、サインアウト、アプリ内削除、ウェブ削除
- 一時D1への復元と、削除済みアカウントを再生成しない確認

## 重大度と時計のリセット

- S0：データ消失、他人のデータ閲覧、認証回避、秘密鍵露出
- S1：同期不整合、復元不能、削除失敗、クォータ回避、継続的5xx
- S2：回避可能な表示・操作上の問題

S0／S1、または保存・認証・同期・API契約・費用制御へ影響する修正が入ったら、
修正版から14日を再計測する。文言、文書、見た目だけの変更はリセットしない。

## 日次記録

`docs/self-test-log.md` に日付、APK SHA、登録冊数、同期確認、5xx、AI利用量、
推定費用、障害を記録する。抜き書き本文や個人情報は記録しない。

開始前に `docs/self-test-log.md` の「自動preflight」がすべて成功していることを確認する。

## 合格

- 14日・10冊を達成
- 未解決S0／S1がゼロ
- 同期、Google復元、旧APK上書き、削除、復元ドリルが成功
- 全プロバイダー費用が2 USD/日、20 USD/月以内
- 最終候補の秘密値スキャンが成功

合格したcommitへタグを付け、同じcommitからAABを作る。Play内部テストで
ストア配布版を24時間確認し、明示的な公開承認後だけproductionへ進める。
